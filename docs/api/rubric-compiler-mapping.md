# Rubric API → compiler v1: explicit field mapping

The [OpenAPI v1 draft](openapi-v1.yaml) describes rubric authoring and version
endpoints. `research.core_mvp.rubric_api.compile_api_rubric_definition()` is the
first executable mapping from one versioned `RubricDefinition` to the current
deterministic compiler. It does **not** implement rubric CRUD, draft cloning,
immutable publication, persistence, RBAC or an HTTP handler. Those parts of
`W9.1–W9.3` remain open.

| API input | Executable compiler input | Rule |
|---|---|---|
| `rubric_key` from create request | `rubric_id` | Stable key; caller supplies it. |
| `title` from create request | `title` | Never generated by the compiler. |
| server-assigned version string | `version` | Required adapter argument; no timestamp-derived version. |
| `definition.max_score` | `max_score` | Explicit; compiler checks sum of criterion weights. |
| `definition.criteria[].criterion_key` | `criterion_id` | ID is preserved. |
| `definition.criteria[].weight` | `weight` | Positive numeric value is preserved. |
| `definition.criteria[].scoring_mode` | fixed proportional checklist rule | Only `PROPORTIONAL_CHECKLIST_V0` executes. |
| `definition.criteria[].checklists[].checklist_key` | `checklist_id` | ID is preserved. |
| `statement` | `statement` | Authored checklist claim; not synthesized from a free-text criterion. |
| `evidence_mode` | `mode` | `LOCAL` or `GRAPH`; `GRAPH` needs at least two authored evidence requirements. |
| `requirements[].requirement_id/description/any_of` | same fields | Exact authored alternatives, not inferred from a sentence. |
| `importance`, `query`, `contradiction_patterns` | same fields | Preserve values when present. Defaults: `REQUIRED`, `statement`, `[]`. |
| `definition.decision_rules` | `decision_rules` | Only compiler-supported keys; omitted values use compiler defaults. |

`RubricCriterion.levels` remains an optional **authoring-only** descriptor in
the draft OpenAPI contract. The current compiler does not implement level-band
scoring; a nonempty `levels` array therefore causes a field-specific error
instead of being ignored or treated as if it affected the proposed score. A
future lifecycle service may store such a draft, but must not publish it as an
executable v1 rubric until level scoring and its tests exist. The deprecated
free-text `RubricChecklist.requirement` is also rejected by the adapter even
when structured `requirements` is present. Old clients must migrate to explicit
`statement` plus atomic `requirements`; otherwise a condition could be silently
lost. Unknown fields fail closed.

The adapter passes a fully explicit rubric object to
`research.core_mvp.rubric.compile_rubric`. That compiler returns a stable
`compiled_id` and `compiled_sha256`. The future persistence layer must save the
exact authoring definition, compiled output, compiler version and assigned
rubric version together; it must reject edits to an already-used/published
version. The adapter alone does not enforce those lifecycle invariants.

`research/tests/test_rubric_api_contract.py` validates a real create request
against the OpenAPI component using JSON Schema, compiles it twice, checks
field preservation/version hashing, and rejects legacy free text, one-part
GRAPH rules, unsupported levels, weight mismatch and unknown fields. These
tests prove the mapping, **not** the rubric HTTP API or publish flow.
